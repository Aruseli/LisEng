# ЛисЭнг (LisEng) — Архитектурный Отчет

## Обзор
LisEng — это продвинутое веб-приложение для изучения английского языка, построенное на стеке Next.js (TypeScript), PostgreSQL, Hasura GraphQL и Hasyx. Приложение реализует комплексный подход к обучению, включая адаптивные планы занятий, системы геймификации, отслеживание прогресса и интеграцию с ИИ для практики разговорных навыков.

---

## 1. Архитектура Базы Данных (PostgreSQL + Hasura)

### 1.1. Основные Таблицы

База данных спроектирована вокруг следующих ключевых сущностей:

#### **`users` (Пользователи)**
- **Цель**: Хранение профилей учащихся.
- **Ключевые поля**: `current_level`, `target_level`, `exam_date`, `daily_goal_minutes`.
- **Особенности**: Настройки по умолчанию для времени и места занятий.

#### **`study_stages` (Этапы Обучения)**
- **Цель**: Определение структуры курса.
- **Ключевые поля**: `level_from` → `level_to`, `start_month`, `end_month`, `focus`.
- **Пример**: Этапы A2→A2+, A2+→B1, B1→B1+, B1+→B2.

#### **`weekly_structure` (Еженедельное Расписание)**
- **Цель**: Шаблон активностей для каждого дня недели на каждом этапе.
- **Связь**: `stage_id` → `study_stages`.
- **Типы активностей**: grammar, vocabulary, reading, listening, writing, speaking, ai_practice.

#### **`daily_tasks` (Ежедневные Задания)**
- **Цель**: Конкретные задачи для пользователей.
- **Ключевые поля**: `user_id`, `task_date`, `type`, `status` (pending/in_progress/completed/skipped).
- **Особенности**: Поле `ai_context` для генерации ИИ-заданий, `suggested_prompt`.
- **Индекс**: `(user_id, task_date)` для быстрого поиска задач за день.

#### **`vocabulary_cards` (Карточки Слов)**
- **Цель**: Система распознавания с повторением (SRS).
- **Ключевые поля**: `next_review_date`, `correct_count`, `incorrect_count`, `difficulty` (new/learning/review/mastered).
- **Индекс**: `(user_id, next_review_date)` для выборки карточек на повтор.

#### **`review_history` (История Повторов)**
- **Цель**: Журнал проверок слов.
- **Ключевые поля**: `was_correct`, `response_time_seconds`.
- **Связь**: `card_id` → `vocabulary_cards`.

#### **`progress_metrics` (Метрики Прогресса)**
- **Цель**: Ежедневная статистика по пользователю.
- **Ключевые поля**: `words_learned`, `tasks_completed`, `study_minutes`, `accuracy_*` (по 5 навыкам).
- **Индекс**: `(user_id, date)`.

#### **`streaks` (Стрики)**
- **Цель**: Отслеживание последовательных дней обучения.
- **Ключевые поля**: `current_streak`, `longest_streak`, `last_activity_date`.
- **Уникальность**: Один ряд на пользователя (`UNIQUE(user_id)`).

#### **`achievements` (Достижения)**
- **Цель**: Система наград и мотивации.
- **Ключевые поля**: `type` (streak_7, words_100, tasks_50, level_up), `title`, `icon`.

#### **`stage_progress` (Прогресс по Этапам)**
- **Цель**: Отслеживание выполнения требований этапа.
- **Ключевые поля**: `tasks_completed`, `tasks_total`, `words_learned`, `errors_pending`, `average_accuracy`, `status` (in_progress/ready_for_test/test_passed/completed).
- **Индекс**: `(user_id, stage_id)`.

#### **`stage_requirements` (Требования Этапов)**
- **Цель**: Правила перехода между этапами.
- **Типы требований**: tasks_completed, words_learned, errors_reviewed, accuracy_threshold, test_passed.
- **Значения**: `requirement_value` (целое), `requirement_threshold` (десятичное).

#### **`stage_tests` (Тесты Этапов)**
- **Цель**: Проверка готовности к переходу.
- **Ключевые поля**: `test_type`, `questions` (JSONB), `user_answers` (JSONB), `score`, `passed`, `feedback` (JSONB).

#### **`ai_sessions` (Сессии с ИИ)**
- **Цель**: Логирование взаимодействий с нейросетью.
- **Ключевые поля**: `type` (speaking, writing, grammar_drill, vocabulary, reading), `conversation` (JSONB массив сообщений), `feedback` (JSONB).

#### **`error_log` (Книга Ошибок)**
- **Цель**: Систематизация ошибок для повторения.
- **Ключевые поля**: `category`, `subcategory`, `mistake`, `correction`, `reviewed`, `next_review_date`.

#### **`shu_ha_ri_progress` и `shu_ha_ri_tests` (Японские Методики)**
- **Цель**: Реализация подходов Кумон, Шу-Ха-Ри, Active Recall.
- **Особенности**: Отслеживание стадий освоения (`shu`, `ha`, `ri`), тестирование понимания.

#### **`lesson_snapshots` (Слепки Уроков)**
- **Цель**: Фиксация результатов каждого занятия.
- **Ключевые поля**: `lesson_type`, `performance_score`, `problem_areas`, `mastery_level`, `kaizen_metrics` (JSONB).

---

### 1.2. Система OPTIONS (Расширяемые Настройки)

Внедрена гибкая система опций (на базе таблицы `options`), позволяющая хранить произвольные метаданные для любой сущности:

- **Пользователи**: `displayName`, `timezone`, `avatar`, `friend_id`, `notifications`.
- **Этапы/Уроки**: `user_id`, `title`, `mark_id`, `route_id`, `zone_id`.
- **Сессии ИИ**: `auto_snapshot`, `session_goal`, `time_limit_minutes`.
- **Kumon-прогресс**: `mastery_threshold`, `difficulty_increase`.
- **Active Recall**: `sm2_initial_ease`, `sm2_min_interval`, `sm2_max_interval`.
- **Shu-Ha-Ri**: `shu_threshold`, `ha_threshold`, `ai_analysis_enabled`.
- **Глобальные опции**: `brain_*` параметры для нейросетевых вычислений.

**Мета-атрибуты**:
- `multiple: true` — разрешение на множественные значения (массив).
- `tables: [...]` — ограничение ссылок на конкретные таблицы (внешние ключи).
- `permission: {...}` — проверки доступа на уровне БД (вставка/обновление).

---

### 1.3. Индексы и Производительность

Созданы индексы для всех частых запросов:
- `idx_daily_tasks_user_date` — задачи пользователя за день.
- `idx_vocabulary_next_review` — карточки на ближайший повтор.
- `idx_progress_metrics_user_date` — метрики по дням.
- `idx_stage_progress_user_stage` — прогресс по этапам.
- `idx_stage_tests_user_stage` — результаты тестов.

**Триггеры**:
- Автоматическое обновление `updated_at` при изменении записей (`update_updated_at_column`).

## 2. Архитектура Ролей и Доступов

### 2.1. Аутентификация и Сессии

Используется **NextAuth.js** (через `hasyx/components/auth/oauth-buttons`) для управления сессиями:
- OAuth-авторизация (Google, GitHub и др.).
- JWT-токены для stateless аутентификации.
- Хранение сессий через `useSession` хук (hasyx).

**Поле `instruction_language`** в таблице `users` определяет язык интерфейса и инструкций (по умолчанию `ru`).

### 2.2. Управление Доступом (Hasura + Hasyx)

Все запросы к БД проходят через **Hasura GraphQL Engine**, который обеспечивает:
- **Row-level security (RLS)**: Пользователи видят только свои данные (через `user_id`).
- **Column-level security**: Ограничение на доступ к колонкам.
- **Проверки в OPTIONS**: Дополнительные ограничения на вставку/обновление через мета-правила.

**Пример проверки в OPTIONS** (добавление друга):
```javascript
permission: {
  insert: {
    table: 'options',
    where: { key: { _eq: 'fio' }, item_id: { _eq: '${TO_ID}' } },
    limit: 1
  }
}
```

### 2.3. Роли в Системе

Хотя RBAS (Role-Based Access Control) явно не декларирован, уровни доступа вытекают из:
- **Владельца данных**: Пользователь — владелец своих `user_id` записей.
- **Администратора**: Доступ через `HASURA_ADMIN_SECRET` для серверных операций (CRON, фоновые задачи).
- **Системных ролей**: ИИ-агенты (генерация контента, проверка тестов).

## 3. Система Геймификации

### 3.1. Стрики (Streaks)

**Таблица `streaks`**:
- `current_streak` — текущая серия дней без перерыва.
- `longest_streak` — исторический максимум.
- `last_activity_date` — дата последней активности.

**Механика**: Обновление `last_activity_date` при любом прогрессе (задача, карточка, сессия). Если дата прерывается, стрик сбрасывается.

**Достижения**:
- `streak_7` — 7-дневный стрик (медаль/значок в `achievements`).

---

### 3.2. Достижения (Achievements)

**Таблица `achievements`**:
- `type` — тип достижения (`streak_7`, `words_100`, `tasks_50`, `level_up`).
- `title`, `description`, `icon` — визуальные атрибуты для отображения.

**Логика**:
- Срабатывает при выполнении условий (см. сервисы проверки).
- Отображается в `ProgressTab` компоненте списком.

---

### 3.3. Очки и Прогресс

Хотя явных «очков» (XP) нет, прогресс измеряется через:
1. **`tasks_completed`** — выполненные задания (целевой процент от общего).
2. **`words_learned` — выученные слова (порог для этапа).
3. **`study_minutes` — затраченное время (дневная цель).

**Визуализация**:
- **Radar Chart** (радар) — сравнение метрик по неделям (слова, задачи, минуты).
- **Polar Area** — общий объем прогресса по неделям.

## 4. Система Рейтингов и Групп

### 4.1. Рейтинги (Accuracy)

Точность выполнения заданий фиксируется в `progress_metrics`:
- `accuracy_grammar`
- `accuracy_vocabulary`
- `accuracy_listening`
- `accuracy_reading`
- `accuracy_writing`

**Использование**:
- В `stage_progress.average_accuracy` — усредненная точность этапа.
- В требованиях этапа (`stage_requirements` с типом `accuracy_threshold` — минимум 0.75 или 75%).

**Логика расчета**:
```typescript
StageProgressionService.calculateAverageAccuracy(metrics)
```
Среднее по всем ненулевым значениям 5 навыков.

### 4.2. Группы

Явных таблиц для групп (классов, команд) в текущей схеме **нет**. Однако, в коде упоминаются:
- **`groups`** (в `app/hasyx/groups/`) — вероятная вкладка для управления группами (через Hasura).
- **Атрибут `friend_id`** в `options.users` — список друзей (множественный UUID), возможно, используется для создания неформальных групп/сообществ.

**Вывод**: Групповая функциональность (лидеры, соревнования) не реализована в текущей версии, но предусмотрена через опции и внешние интерфейсы.

---

### 4.3. Версии Курса (Стадии)

**Таблица `study_stages`** определяет версии курса:

| Название | Уровни | Месяцы | Фокус |
|----------|--------|--------|-------|
| A2 → A2+ | 1–4 | Укрепление базы, ритуалы |
| A2+ → B1 | 5–8 | Расширение словаря, сложная грамматика |
| B1 → B1+ | 9–12 | Подготовка к ОГЭ, автоматизация навыков |
| B1+ → B2 | 13–18 | Шлифовка, уверенность, финальная подготовка |

**Версионирование материалов**:
- Задания (`daily_tasks`) привязаны к `stage_id`.
- При смене этапа обновляется расписание (`weekly_structure`) и требования (`stage_requirements`).

## 5. Паттерны Проектирования

### 5.1. Многоуровневая Архитектура (Clean Architecture Style)

```
Frontend (Next.js/React)
  ↓
API Routes (Next.js /api/...)
  ↓
Service Layer (lib/)
  - lesson-snapshots/
  - schedule/
  - vocabulary/
  - stage-progression.ts
  ↓
Data Access (Hasyx Client + Hasura GraphQL)
  ↓
Database (PostgreSQL)
```

**Характеристики**:
- Отсутствие прямого SQL в коде (через GraphQL/Hasyx).
- Сервисы содержат бизнес-логику, независимую от БД.
- Компоненты используют хуки (`useDashboardData`, `useAISession`) для изоляции данных.

---

### 5.2. Система Hasyx (Абстракция над Hasura)

**Что такое Hasyx**:
- TypeScript-клиент поверх Hasura GraphQL.
- Генерация типов и мутаторов на основе схемы (`hasura-schema.json`).
- Методы: `select`, `insert`, `update`, `delete` с проверкой прав.

**Преимущества**:
- Замена GraphQL-кодогенерации (Apollo) на runtime-запросы.
- Упрощение кривой обучения (вместо SDL/фрагментов — JS-объекты).
- Встроенная пагинация, фильтры, связи.

**Пример использования**:
```typescript
const tasks = await hasyx.select({
  table: 'daily_tasks',
  where: { user_id: { _eq: userId }, task_date: { _eq: date } },
  returning: ['id', 'title', 'status']
});
```

---

### 5.3. Микросервис-подобные модули (Modular Services)

Каждый домен имеет свой сервис:

- **`LessonSnapshotService`** — создание слепков уроков.
- **`ShuHaRiService`** — управление тестами и прогрессом Шу-Ха-Ри.
- **`ScheduleService`** — крон-задачи и напоминания.
- **`MethodologyAdvisor`** — ИИ-рекомендации на основе метрик.

**Признаки хорошего модуля**:
- Единая ответственность (SRP).
- Внедрение зависимостей (через конструкторы `Hasyx`, `ScheduleService`).
- Независимость от HTTP (можно запускать в фоне/CRON).

---

### 5.4. Observer / Pub-Sub (CRON и Мониторы)

**Библиотека CRON**:
- Запуск фоновых задач по расписанию (`CronCreate`, `Monitor`).
- Пример: проверка готовности каждую ночь, создание еженедельных тестов.

**Мониторы (Monitor)**:
- Слежение за изменениями (например, лог-файл, API-поллинг).
- Событийная модель — каждая строка stdout генерирует уведомление.

**Пример использования**:
```typescript
Monitor({
  command: 'tail -f lesson.log | grep --line-buffered "ERROR"',
  description: 'errors in deploy.log',
  timeout_ms: 300000,
  persistent: true
});
```

---

### 5.5. Стратегия (Strategy Pattern) — Алгоритмы Адаптации

**SM2 Algorithm** (`lib/lesson-snapshots/sm2-algorithm.ts`):
- Адаптивное планирование повторений карточек.
- Интерфейс `SM2Params` (качество ответа, интервал, множитель).
- Функция `calculateSM2` возвращает новый интервал.

**Kumon Progression**:
- Уровни 1–7 с порогами `mastery_threshold` и `difficulty_increase`.
- Достижение 3 правильных ответов подряд → повышение уровня.

**Выбор стратегии в runtime**:
```typescript
const strategy = user.preferences.methodology; // 'sm2' | 'kumon' | 'kaizen'
const service = MethodologyAdvisor.getStrategy(strategy);
service.reviewCard(card, result);
```

---

### 5.6. Фабрика (Factory Pattern)

**`Generator` (Hasyx)**:
- Создает валидаторы и мутаторы для таблиц на основе схемы.
- Вызов `Generator(schema)` возвращает фабрику опций/запросов.

**AI Factory** (`lib/ai/llm.ts`):
- Получение ИИ-модели в зависимости от контекста (GPT-4, Claude, локальная).
- Инкапсуляция промптов и парсинга JSON.

---

### 5.7. Шаблонный Метод (Template Method) — Stage Progression

**`StageProgressionService.checkStageRequirements`**:
- Общий алгоритм проверки:
  1. Для каждого требования вызвать `switch (type)`
  2. Рассчитать `current_value`
  3. Сравнить с порогом
  4. Сформировать `message`

**Подклассы/вариации** не нужны — вариативность достигается через конфигурацию требований в БД.

---

### 5.8. Мемоизация и Хуки (React)

Использование `useMemo` и кастомных хуков для производительности:
```typescript
const tasks = useMemo(() => (dashboard?.plan?.tasks ?? []), [dashboard?.plan?.tasks]);
```

**Кастомные хуки**:
- `useDashboardData` — агрегация данных для главной страницы.
- `useAISession` — управление сессией ИИ и историей.
- `useVerbProgress` — ход изучения глаголов.

## 6. AI-Интеграция и NLP

### 6.1. LLM Сервис (`lib/ai/llm.ts`)

- **Модели**: Интеграция с OpenAI, Anthropic (Claude), возможно локальными.
- **Кэширование промптов**: Повторное использование контекста.
- **Парсинг JSON**: `parseJSONResponse` для структурированных ответов (тесты, фидбек).

### 6.2. Генерация Заданий

- **`useAISession`** — отправка сообщений, поддержка контекста.
- **`ShuHaRiService.generateTestQuestions`** — создание вопросов на основе слепков и навыков.
- **`MethodologyAdvisor`** — анализ слепков и выдача рекомендаций (Kaizen, Kumon).

### 6.3. Автоматическая Проверка

- **Орфография/грамматика**: Через LLM (промпт с корректурой).
- **Точность ответов**: Сравнение строк (наивный метод) или семантическое сходство (векторное пространство).
- **Генерация фидбека**: Анализ ошибок и вывод улучшений.

## 7. Выводы и Рекомендации

### Сильные стороны архитектуры

1. **Гибкость БД**: Система OPTIONS позволяет добавлять новые метаданные без миграций.
2. **Чистота сервисов**: Логика изолирована от транспорта (GraphQL/HTTP).
3. **Масштабируемость**: Микросервисные модули и CRON-задачи.
4. **Геймификация**: Многогранная (стрики, достижения, слои сложности, японские методики).

### Зоны улучшений

1. **Кэширование**: Нет явного кэша (Redis/Memory) для частых запросов (прогресс, карточки).
2. **Реал-тайм**: Не хватает WebSocket/Broadcast для мгновенных обновлений (новое достижение, задача).
3. **Тестирование**: Сервисы и компоненты нуждаются в unit/e2e тестах (Jest/Cypress).
4. **Оптимистичные обновления**: UI может отставать при медленном ИИ-ответе (добавить `useMutation` с кэшем).
5. **RBAC**: Расширение ролей (учитель/ученик, админ) для группового обучения.

### Паттерны для внедрения

- **CQRS**: Разделение команд (изменения) и запросов (чтение) для сложной аналитики.
- **Event Sourcing**: Хранение истории всех действий пользователя для точного отката/аналитики.
- **Saga Pattern**: Управление длительными процессами (например, создание курса состоит из 10 этапов).
- **Feature Flags**: Включение/выключение ИИ-функций через OPTIONS без деплоя.
